BẢN ĐỒ BỘ NHỚ MCU (STM32 / ESP32)

Phân bổ bộ nhớ chuẩn trong lập trình C/C++ vi điều khiển
FLASH Non-Volatile
0x0800_0000 (STM32) | 0x4200_0000 (ESP32)
.isr_vector / .text Mã máy (Executable Code)
Chứa Bảng vector ngắt (ISR) và toàn bộ mã lệnh của chương trình. CPU đọc và thực thi trực tiếp từ Flash hoặc nạp vào IRAM/ITCM lúc boot.
void main(void) { ... }
void USART1_IRQHandler(void)
.rodata Hằng số (Read-Only Data)
Lưu hằng số chỉ đọc, chuỗi literal và các bảng tra (look-up table).
const int MAX_RETRY = 5;
"Hello World\n"
RAM Volatile
0x2000_0000 (STM32) | 0x3FC8_0000 (ESP32)
.data Biến toàn cục (Init ≠ 0)
Chứa biến global hoặc static đã khởi tạo giá trị ban đầu khác 0. Giá trị khởi tạo được lưu ở Flash và copy sang RAM lúc khởi động.
int g_system_state = 1;
static float factor = 2.5f;
.bss Biến toàn cục (Init = 0 / Uninit)
Chứa biến global hoặc static không khởi tạo hoặc gán bằng 0/NULL. Tự động xóa về 0 lúc boot (không tốn dung lượng Flash).
int g_counter;
char* p_buffer = NULL;
.heap Bộ nhớ động (Dynamic Memory)
Vùng nhớ cấp phát động trong quá trình chạy chương trình bằng các hàm chuẩn C/C++.
malloc(), calloc(), realloc(), free()
▼ Heap phát triển xuống | Stack phát triển lên ▲
Vùng nhớ trống (Free Memory Pool)
.stack Bộ nhớ tạm (Local Context)
Lưu biến cục bộ, tham số truyền vào hàm, địa chỉ trả về (return address) và ngữ cảnh ngắt (context switch).
int temp = 0; // khai báo trong hàm
1. Kích thước các vùng bộ nhớ được xác định thế nào?
Phân vùng Thời điểm xác định kích thước Yếu tố quyết định
.text & .rodata Tĩnh (Lúc biên dịch) Số lượng câu lệnh, thư viện và hằng số/chuỗi literal.
.data & .bss Tĩnh (Lúc biên dịch) Tổng số lượng biến global và static được khai báo.
.stack Tĩnh (Cấu hình trước) Khai báo cố định trong file Linker Script (.ld hoặc .s).
.heap Động (Lúc chạy - Runtime) Lượng bộ nhớ yêu cầu qua các hàm malloc()/new tại từng thời điểm.
2. Các vùng cần đặc biệt quan tâm khi lập trình Nhúng
  • Vùng .data & .bss (RAM Tĩnh): Chiếm RAM vĩnh viễn ngay từ lúc bật nguồn. Nếu quá lớn sẽ làm hẹp không gian dành cho Stack và Heap.
  • Vùng .stack (Bộ nhớ tạm): Dễ gây ra lỗi Stack Overflow nguy hiểm. Lỗi này xảy ra khi gọi hàm lồng nhau quá sâu, truyền biến cục bộ kích thước lớn (như buffer lớn), hoặc ngắt chồng ngắt làm Stack tràn sang các vùng nhớ khác gây crash/reset MCU.
  • Vùng .heap (Cấp phát động): Nguy cơ cao gặp lỗi Memory Leak (rò rỉ bộ nhớ) và Memory Fragmentation (phân mảnh bộ nhớ), khiến hệ thống hoạt động chập chờn hoặc ngưng trệ sau một thời gian vận hành dài.
3. Tips tối ưu hóa bộ nhớ (Optimization Guidelines)
  • Tối ưu RAM tĩnh (.data / .bss): Đẩy các bảng tra cứu (look-up table), mảng hằng số và chuỗi sang vùng Flash (.rodata) bằng từ khóa const. Ép kiểu dữ liệu nhỏ nhất có thể (dùng uint8_t thay vì int).
  • Bảo vệ vùng .stack: Không khai báo mảng buffer lớn dạng biến cục bộ bên trong hàm; hãy dùng từ khóa static để đẩy mảng đó sang .bss. Hạn chế đệ quy và tránh truyền tham số dạng cấu trúc lớn (nên dùng con trỏ const T*).
  • Quản lý .heap an toàn: Hạn chế tối đa dùng malloc()/free() trong vi điều khiển. Nếu bắt buộc phải dùng, hãy cấp phát tĩnh toàn bộ trong bước khởi tạo hệ thống (setup) và không cấp phát/giải phóng liên tục trong vòng lặp chính.
  • Tối ưu dung lượng Flash (.text): Bật các flag tối ưu kích thước file biên dịch trên IDE (ví dụ: -Os trên GCC). Hạn chế dùng các hàm tốn bộ nhớ như printf(), sprintf() nếu không thực sự cần thiết.
